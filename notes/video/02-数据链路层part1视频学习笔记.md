## 一、视频主线

本视频主要覆盖数据链路层中的**介质访问控制 + 无线局域网竞争机制 + 差错检测/纠错前半部分**。

从视频板书和真题串讲可以确认的主线：

CDMA → CSMA/CD → 最小帧长与争用期 → 二进制指数退避 → CSMA/CA → DIFS/SIFS/PIFS → RTS/CTS/ACK → IEEE 802.11 → CRC → 奇偶校验/海明码。

## 二、CDMA

视频把 CDMA 作为码分复用重点讲解。

每个站点拥有自己的码片序列。发送：

- 比特 1：发送自己的码片序列。
- 比特 0：发送自己的码片序列的反码。

接收端若要恢复某站点数据，就用“收到的混合序列”和目标站点码片序列做规格化内积。

若码片长度为 (m)，则按视频的计算方式：

$$rac{1}{m}sum_{i=1}^{m}r_i c_i$$

典型结果：

- 得到 (+1)：该站点发送 1。
- 得到 (-1)：该站点发送 0。
- 得到 0：该站点此时未发送。

视频用 2014 年 408 CDMA 真题进行了完整计算。

## 三、CSMA/CD：核心思想

视频明确强调：

- **先听后发**
- **边听边发**
- **冲突停发**
- **随机重发**

发送流程：

1. 发送前先监听信道。
2. 信道忙则继续监听。
3. 信道空闲则开始发送。
4. 发送过程中持续检测碰撞。
5. 若检测到碰撞，立即停止发送，并发送强化冲突信号。
6. 进入二进制指数退避，等待随机时间后重发。

CSMA/CD 主要用于传统共享式有线以太网。

## 四、争用期与碰撞检测

视频反复用“最远两个站点”推导碰撞检测时间。

设单向传播时延为 (	au)，最坏情况下，一个站点必须在发送后的：

$$2	au$$

内仍能够检测到碰撞。

因此争用期可理解为：

$$2	au$$

这个结论直接连接到最小帧长。

## 五、最小帧长

视频板书给出推导：

为了保证最坏情况下发生碰撞时，发送端仍处于发送状态，帧发送时间至少覆盖争用期。

因此：

$$T_{frame}ge 2	au$$

若链路速率为 (R)，则最小帧长满足：

$$L_{min}ge 2	au R$$

视频明确强调传统以太网最小帧长：

$$64B=512bit$$

做题时常见变形：

- 给速率和传播时延，求最小帧长。
- 给最小帧长和速率，求最大网络跨度/传播时延。
- 给中继器/Hub附加延时，要把设备延时并入冲突检测往返时间。

## 六、二进制指数退避

视频把退避算法作为 CSMA/CD 高频考点。

第 (i) 次碰撞后，从一个随碰撞次数扩大的整数集合中随机取数，再乘以基本争用时间片。

核心思想：

- 碰撞次数越多，可选择的随机等待范围越大。
- 目的是降低多个站点再次同时重发导致冲突的概率。

视频串讲了 2023 年关于“连续多次冲突后最长退避时间”的真题。

## 七、CSMA/CD 高频判断

看到下列条件时立即触发：

- “边发送边检测” → CSMA/CD。
- “最小帧长” → (2	au R)。
- “100Base/10Base + 最大站距” → 先求最大往返碰撞检测时间。
- “连续第 k 次冲突” → 二进制指数退避。
- “无线局域网” → 一般不能直接套 CSMA/CD。

视频明确强调 CSMA/CD 是有线共享介质的碰撞**检测**机制，而无线侧重点转向碰撞**避免**。

## 八、CSMA/CA

视频在无线局域网部分转向 CSMA/CA。

核心思想：

- 无线环境中很难像有线以太网那样在发送同时可靠检测冲突。
- 因此采用“尽量避免碰撞 + 显式确认”的方式。

视频板书概括：

1. 站点发送前监听信道。
2. 信道在 DIFS 内持续空闲后，进入竞争/退避过程。
3. 随机选择退避计数。
4. 信道忙时冻结退避计时器。
5. 信道重新空闲并满足 DIFS 后继续倒计时。
6. 计数减到 0 后发送。
7. 正确接收后由接收方返回 ACK。
8. 未收到 ACK 时按规则重传并扩大退避范围。

## 九、帧间间隔 IFS

视频重点区分：

- SIFS：最短，用于一次对话内部的连续帧，例如 CTS、ACK 等。
- DIFS：普通异步数据竞争前使用。
- PIFS：视频作为 PCF 相关间隔提到。

做题判断时：

**一次已有通信过程内部的响应帧通常使用更短的 SIFS，从而拥有更高优先级。**

视频用 2020 年 408 的 IFS 时序题进行了讲解。

## 十、RTS/CTS

视频详细画了无线预约时序：

RTS → SIFS → CTS → SIFS → DATA → SIFS → ACK

RTS（Request To Send）用于请求发送，CTS（Clear To Send）用于允许发送。

作用：

- 让周围其他站点知道这次通信将占用信道一段时间。
- 降低隐藏站等问题导致的冲突概率。

视频强调 RTS/CTS 不是每次都必须使用，但题目一旦给出该流程，就按上面的 SIFS 时序判断。

## 十一、隐藏站与无线竞争

视频用无线覆盖范围示意图解释：

两个站点可能互相听不到，但都能影响同一个接收端，这会产生隐藏站问题。

因此无线局域网不能只依赖“我听不到别人，所以我就发”，还需要退避、确认以及可选的 RTS/CTS 预约机制。

## 十二、CRC

视频后段进入差错检测。

CRC 做题流程：

1. 把生成多项式写成二进制除数。
2. 若生成多项式最高次数为 (r)，原数据后补 (r) 个 0。
3. 做模 2 除法（异或，不借位）。
4. 得到 (r) 位余数。
5. 发送端把余数拼到原数据后。
6. 接收端再次除以同一生成多项式。
7. 余数为 0 → 通过 CRC 检验；非 0 → 检出错误。

视频强调：

**CRC 具有检错能力，但链路层使用它时通常是“检测到错误就丢弃”，CRC 本身不负责自动纠正错误。**

## 十三、奇偶校验

视频用奇校验举例：

- 奇校验：整个码字中 1 的总数为奇数。
- 偶校验：整个码字中 1 的总数为偶数。

单个奇偶校验位能够检测部分错误，但不能定位错误位置。

## 十四、海明码

视频最后进入海明码。

板书方法：

- 校验位放在 (1,2,4,8,ldots) 等 2 的幂位置。
- 数据位放在剩余位置。
- 每个校验位负责检查“位置编号的二进制表示中对应位为 1”的那些位置。

若数据位有 (m) 位、校验位有 (r) 位，需满足足够的校验状态来区分“无错 + 各个单比特错误位置”。

视频示例对 4 bit 数据配置 3 个校验位，并通过各校验组的结果定位到具体出错位，再反转该位完成单比特纠错。

## 十五、视频中的高频真题锚点

- 码片序列、规格化内积 → CDMA。
- 共享有线以太网、冲突检测 → CSMA/CD。
- 最大站距/最小帧 → (2	au) 与 (2	au R)。
- 多次冲突 → 二进制指数退避。
- 无线局域网 + 退避 + ACK → CSMA/CA。
- RTS/CTS + 多个 IFS → SIFS/DIFS 判断。
- 生成多项式 → CRC。
- 校验位位于 1、2、4、8… → 海明码。
