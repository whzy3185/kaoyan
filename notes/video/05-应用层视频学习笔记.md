## 一、视频主线

本视频可确认的主要顺序：

DNS 层次结构 → DNS 查询过程与查询次数 → FTP → 电子邮件（SMTP/POP3）→ HTTP → HTTP/1.1 连接方式与时延 → 真题串讲。

## 二、DNS 域名层次结构

视频用树形结构展示域名空间。

从上到下包括：

- 根
- 顶级域名
- 二级域名
- 三级/更多级域名

域名本质上沿 DNS 树从具体主机逐级向根组织，例如：

`www.abc.xyz.com`

视频强调做题时要正确拆分域名层次，不能把整个字符串误当成一个单独“域”。

## 三、DNS 服务器层次

视频画出：

- 本地域名服务器
- 根域名服务器
- 顶级域名服务器
- 权限/授权域名服务器

解析一个没有缓存的域名时，需要沿层次逐级找到负责目标域的权威服务器。

## 四、递归查询与迭代查询

视频用 2016、2020 真题反复讲查询次数。

### 递归

收到查询的服务器继续替请求方完成后续查询，再把最终结果返回。

### 迭代

服务器不代替请求方完成整个解析，只告诉它“下一步应该去问谁”。

视频中典型结构是：

- 主机向本地域名服务器发起查询。
- 本地域名服务器再根据题目设定访问根、顶级、权威服务器。

做“最少/最多 DNS 查询次数”题时，必须先读题确认：

- 哪些服务器有缓存。
- 哪一级采用递归。
- 哪一级采用迭代。
- 目标域名有几级。

不能机械背固定次数。

## 五、DNS 与网页访问时延

视频使用 2020 真题把 DNS 与 HTTP 时延放在一起。

统一方法：

1. 先算域名解析需要几个 RTT。
2. 再算 TCP 建连 RTT。
3. 再算 HTTP 请求/响应所需 RTT。
4. 若网页还有引用对象，再根据持续/非持续、流水线/非流水线继续加。

所以 DNS 题常常并不是独立计算，而是应用层综合时延题的前半部分。

## 六、FTP

视频中明确讲到 FTP：

- 采用 C/S 模型。
- 基于 TCP。
- 控制连接与数据连接分开。

### 控制连接

- 用来传递连接请求、命令等控制信息。
- 在一次 FTP 会话期间通常持续保持。
- 教学中使用服务器端口 21。

### 数据连接

- 用于真正传文件。
- 传输一个文件时临时建立。
- 文件传输完成后可关闭，因此与控制连接的生命周期不同。

视频板书特别强调不要把“登录服务器建立的连接”与实际传文件的数据连接混为一谈。

## 七、电子邮件系统

视频用完整流程图讲：

发送方用户代理 → 发送方邮件服务器 → 接收方邮件服务器 → 接收方用户代理。

### SMTP

SMTP 负责：

- 用户代理向发送邮件服务器提交邮件。
- 邮件服务器之间传送邮件。

视频真题中强调：

- SMTP 基于 TCP。
- 传统 SMTP 直接传输 7 bit ASCII 文本内容。

### POP3

接收方用户代理主动从邮件服务器拉取邮件。

视频把 POP3 与 SMTP 的方向关系画得很清楚：

- SMTP：推送邮件到邮件服务器/服务器之间。
- POP3：用户代理从接收方邮件服务器取邮件。

### MIME

视频所在知识树包含邮件内容扩展相关内容。做题时应记住：传统 SMTP 的 7 bit ASCII 限制需要借助 MIME 等扩展机制支持更多类型内容。

## 八、HTTP

视频后段进入 HTTP。

核心特点：

- 应用层协议。
- 基于 TCP。
- HTTP 本身是无状态协议。

## 九、浏览网页的一般过程

视频列出典型步骤：

1. 用户输入 URL。
2. 浏览器分析 URL。
3. DNS 解析服务器域名得到 IP。
4. 浏览器与服务器建立 TCP 连接。
5. 浏览器发送 HTTP 请求。
6. 服务器返回 HTTP 响应。
7. 浏览器解析页面，并继续请求引用对象。
8. 根据连接策略关闭或复用 TCP 连接。

做综合题时，应把 DNS、TCP、HTTP 三层时延分开画出来。

## 十、HTTP 非持续连接

非持续 HTTP 中，一个 TCP 连接通常只完成一个对象的请求/响应。

若先获取 HTML，再获取多个图片对象，就可能需要为不同对象重新建立 TCP 连接。

因此 RTT 开销较大。

## 十一、HTTP 持续连接

HTTP/1.1 默认倾向于持续连接，可以复用已经建立的 TCP 连接。

视频画面重点比较：

- 非流水线持续连接
- 流水线持续连接

### 非流水线

一个请求得到响应后再发送下一个请求。

### 流水线

可连续发出多个请求，不必每个对象都完整等待前一个响应结束。

因此在忽略传输时延等条件时，流水线方式可以减少 RTT 数量。

## 十二、HTTP 页面时延题

视频用“1 个 HTML + 多个图片，每个对象若干 MSS”的时序图训练计算。

做题固定拆成：

1. TCP 建连。
2. 请求 HTML。
3. 接收 HTML。
4. 解析出图片引用。
5. 根据连接方式请求图片。
6. 加上必要的 RTT 与数据传输时间。

题目若说明“忽略 TCP 段传输时延”，就只数 RTT；若给 MSS、对象大小和链路速率，则还要加入实际发送时间。

## 十三、HTTP 请求报文与 Cookie

视频通过 2015 真题展示类似：

- `GET /index.html HTTP/1.1`
- `Host: ...`
- `Connection: close`
- `Cookie: ...`

判断时注意：

- GET 行确定请求的资源路径。
- Host 表示目标主机域名。
- Connection 反映连接策略。
- Cookie 用于让服务器识别/关联此前状态信息。

HTTP 协议本身仍是无状态的；Cookie 是在其上实现状态维持的一种机制。

## 十四、应用层高频做题锚点

- 域名树 + 本地/根/TLD/权威服务器 → DNS。
- “最少/最多查询次数” → 先读缓存与递归/迭代条件。
- FTP 登录/命令 → 控制连接。
- FTP 文件传输 → 数据连接。
- 发邮件到服务器、服务器之间 → SMTP。
- 用户主动取邮件 → POP3。
- 网页访问时延 → DNS RTT + TCP RTT + HTTP RTT。
- HTTP/1.1 → 优先检查持续连接。
- Cookie → HTTP 上层状态维持机制。
