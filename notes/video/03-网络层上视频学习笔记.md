## 二、分组交换中的传输时延与传播时延

视频开头用主机 H1、路由器 R、主机 H2 的流水传输图说明：

- **传输时延**：把一个完整分组的全部比特推入链路所需时间。
- **传播时延**：信号在链路上传播所需时间。

若分组长度为 (L)，链路发送速率为 (R)：

$$d_{trans}=rac{L}{R}$$

多跳存储转发时，必须先把“一个分组经历多少次传输时延、多少次传播时延”数清楚，再列总时延。

视频强调分组流水传输时，不应把每个分组的全部端到端时延简单相加；后续分组会与前面分组在不同链路上重叠传输。

## 三、IPv4 首部

视频集中讲解了 IPv4 基本首部字段。

### 1. 版本

- 4 bit。
- IPv4 时值为 4。

### 2. 首部长度 IHL

- 4 bit。
- 单位是 **4B**。
- 最大值为 15，因此最大首部长度：

$$15	imes4=60B$$

- 基本首部通常为 20B。

做题时，如果 IHL=5：

$$5	imes4=20B$$

### 3. 总长度

- 16 bit。
- 表示 **首部 + 数据** 的总长度。
- 最大理论长度：

$$2^{16}-1=65535B$$

实际发送还受链路 MTU 限制。

### 4. 标识、标志、片偏移

用于 IPv4 分片与重组。

视频把这三个字段作为一个整体理解：

- 同一个原始 IP 数据报的各分片具有相同标识。
- MF 用来标识后面是否还有分片。
- 片偏移表明该分片的数据位于原数据报数据部分的什么位置。

### 5. TTL

视频强调 TTL 可理解为“最大跳数”：

- 每经过一个路由器，TTL 至少减 1。
- 减到 0 时，该分组不能继续正常转发。

### 6. 协议字段

指出 IP 数据报数据部分交给哪个上层协议，例如 TCP、UDP、ICMP 等。

### 7. 首部校验和

IPv4 的首部校验只校验 **IP 首部**，不覆盖数据部分。

## 四、IPv4 分片

视频用 MTU=800B、IPv4 首部20B的真题进行板书推导。

核心判断链：

1. 链路 MTU 限制的是整个 IP 分片长度。
2. 每个分片仍有自己的 IP 首部。
3. 因此先算单个分片最多能装多少数据：

$$	ext{最大数据长度}le MTU-	ext{首部长度}$$

4. 除最后一个分片外，数据长度通常应为 8B 的整数倍。
5. 片偏移的单位是 **8B**。

视频中示例：

- MTU=800B
- 首部=20B
- 最大分片数据不能直接取780B，因为片偏移单位要求。
- 取 776B，即：

$$776=97	imes8$$

所以下一个分片的片偏移可写成 97。

### MF

- 后面还有分片：MF=1。
- 最后一个分片：MF=0。

### 重要做题顺序

**先算可装数据 → 调整为8B整数倍 → 再算分片数 → 再算片偏移。**

## 五、IPv4 地址与分类地址

视频通过板书反复训练“网络号 + 主机号”的拆分。

传统分类地址中，关注：

- A 类
- B 类
- C 类

做题时重点不是只背类别，而是能根据首字节范围或前导比特判断网络号长度，再判断主机号范围。

视频还讨论了特殊地址/不能正常分配给普通主机的地址，因此遇到地址判断题不能只看“数字长得像普通 IPv4”。

## 六、子网掩码

子网掩码本质上把 32 bit IPv4 地址分成：

- 网络/子网部分
- 主机部分

核心运算：

$$	ext{网络地址}=	ext{IP地址 AND 子网掩码}$$

只要题目给出 IP 与掩码，优先转换关键字节为二进制做 AND。

## 七、子网划分

视频用“从主机位借位”的方式解释子网划分。

若借 (n) 位作为子网号，则可形成的子网数与借位数有关；每个子网剩余主机位决定该子网的地址容量。

做题判断链：

1. 原前缀长度是多少。
2. 需要多少子网。
3. 至少借多少位。
4. 新前缀长度是多少。
5. 每个子网地址块大小是多少。
6. 写出每个子网起始地址、广播地址与可分配主机范围。

视频后半部分反复用二叉树式“地址块再切一半”的方法做 VLSM/CIDR 题，这种方法后续教学继续沿用。

## 八、CIDR

CIDR 使用斜线记法：

`IP地址/前缀长度`

例如：

`193.115.21.0/24`

前缀长度为 24，剩余 8 bit 为地址块内变化部分。

若已知一个 CIDR 地址块中的任意一个 IP，只要前缀长度确定，就能够求：

- 地址块最小地址
- 地址块最大地址
- 地址块大小

地址块大小：

$$2^{32-	ext{前缀长度}}$$

## 九、路由聚合

视频使用连续多个 /24 地址块演示路由聚合。

例如要聚合若干连续网络：

1. 把各网络地址写成二进制。
2. 从高位开始寻找共同前缀。
3. 第一个不同位之前的位数，就是聚合后的前缀长度。
4. 聚合网络地址把剩余位全部置 0。

视频特别强调：只有前缀连续且满足边界对齐条件的地址块才能直接合并，不能只因为“数字看起来连续”就随意聚合。

## 十、最长前缀匹配

路由器收到目的 IP 后，可能同时匹配多个路由表项。

最终选择：

**前缀最长的那一条。**

可以理解为：

- /24 比 /16 更具体。
- /32 主机路由比普通网络路由更具体。
- 默认路由 /0 只在没有更具体匹配时兜底。

视频把最长前缀匹配与路由聚合放在一起讲，因为二者都要求熟练处理二进制前缀。

## 十一、视频中的高频做题锚点

看到以下条件时立即触发：

- 分组大小 + 链路速率 → 先算传输时延。
- 多跳存储转发 → 数清传输次数和流水重叠。
- IHL → 单位是 4B。
- MTU + IP首部 → 分片。
- 片偏移 → 单位 8B。
- IP + 掩码 → AND 求网络地址。
- “划分若干子网” → 借位。
- CIDR 多网段合并 → 找最长公共前缀。
- 多条路由都能匹配 → 最长前缀匹配。
