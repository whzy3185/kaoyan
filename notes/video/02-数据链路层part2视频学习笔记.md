## 一、视频主线

海明码收尾 → 停止-等待 ARQ → 滑动窗口 → GBN → SR → 信道利用率 → IEEE 802.11 帧地址 → VLAN/802.1Q → 交换机自学习。

大量时间用于 408 真题与板书推导。

## 二、海明码错误定位

视频开头继续海明码。

通过各校验组重新计算是否满足奇/偶校验，可以得到一个由校验结果组成的二进制编号。

这个编号直接指出发生单比特错误的位置。

典型流程：

1. 按校验位负责范围重新分组。
2. 每组重新计算校验。
3. 把各组“正确/错误”的结果组成二进制位置号。
4. 若结果非 0，则定位到具体出错位。
5. 反转该位完成单比特纠错。

## 三、停止-等待协议

视频随后进入可靠传输。

停止-等待的基本思想：

- 发送方一次只发送一个数据帧。
- 发送后等待确认 ACK。
- 收到正确 ACK 后才发送下一帧。
- 超时未收到 ACK 时重传。

为区分“新帧”和“重传的旧帧”，只需要很小的序号空间，常见交替使用 0/1。

视频板书特别强调：

- 数据帧可能丢失。
- ACK 也可能丢失。
- 因此必须有**超时计时器**。
- 接收方必须能识别重复帧。

## 四、滑动窗口思想

为了提高信道利用率，不能总是“发一帧，空等一个 RTT”。

滑动窗口允许发送方在收到前一帧 ACK 之前继续发送多个帧，使链路上同时存在多个未确认帧。

做题核心变量：

- 序号位数 (n)
- 发送窗口 (W_T)
- 接收窗口 (W_R)

## 五、GBN（后退 N 帧）

视频用时序图详细讲 GBN。

特点：

- 发送方可以连续发送多个帧。
- 接收窗口通常为 1。
- 接收方只按序接收。
- 使用累计确认。
- 若某个较早帧超时，发送方需要从该帧开始，把它以及后续尚未确认的帧一起重传。

例如某帧超时：

**重传出错/超时帧 + 其后的所有未确认帧。**

### GBN 窗口上限

若序号字段为 (n) bit，为避免新旧帧混淆，常用结论：

$$W_Tle 2^n-1$$

视频的真题推导中反复利用该结论求“帧序号至少需要多少位”。

## 六、SR（选择重传）

视频把 SR 与 GBN 对比。

SR 的核心特点：

- 接收窗口可以大于 1。
- 接收方允许缓存乱序到达的正确帧。
- 某帧出错/超时后，只重传需要重传的指定帧。
- 每个未确认帧通常需要独立管理超时。

为避免序号回绕造成新旧帧混淆，视频板书给出窗口限制：

$$W_Tle W_R$$

并使用常见最大窗口结论：

$$W_T^{max}=W_R^{max}=2^{n-1}$$

## 七、ACK、NAK 与累计确认

视频中既讲 ACK，也出现 NAK。

- ACK：肯定确认。
- NAK：否定确认，表示接收方认为某个帧有问题并请求重传。

GBN 常结合累计确认：

某个 ACK 表示“该序号之前按序到达的帧已经正确接收，并期待下一个序号”。

做时序图时必须先确认题目中 (R_{x,y})、ACK 序号的定义，再解释它究竟确认到哪一帧。

## 八、双向 GBN 综合题

视频用 2017 年 408 的双向 GBN 综合题详细演示：

- 发送序号和确认序号均为 3 bit。
- 双方采用捎带确认。
- 需要从时序图中判断：
  - 哪些帧已经被对方正确接收。
  - 当前还能继续发多少帧。
  - 超时后从哪一帧开始重传。
  - 最大信道利用率。

这类题的做法：

1. 明确发送窗口大小。
2. 沿时间轴逐帧标记已发送、已确认、未确认。
3. 解释每个确认号的语义。
4. 碰到超时，从 GBN 最早未确认帧开始回退。
5. 最后再处理信道利用率。

## 九、信道利用率

视频给出统一思想：

$$U=rac{	ext{一个周期内真正发送有效数据的时间}}{	ext{一个发送周期总时间}}$$

对停止-等待，如果考虑：

- 数据帧发送时延 (T_D)
- RTT
- ACK 发送时延 (T_A)

则视频板书形式为：

$$U=rac{T_D}{T_D+RTT+T_A}$$

若忽略 ACK 发送时延：

$$U=rac{T_D}{T_D+RTT}$$

其中：

$$T_D=rac{L}{C}$$

(L) 是数据帧长度，(C) 是链路速率。

## 十、滑动窗口达到满利用率

发送窗口足够大时，可以在第一个帧 ACK 返回之前持续把新帧塞入链路，从而减少等待造成的空闲。

做题判断链：

1. 先算一个数据帧发送时延。
2. 再确定从首帧开始发送到确认返回的时间。
3. 看这段时间里要连续塞入多少个帧才能不让发送端空闲。
4. 用所需窗口大小反推序号位数。

视频用 2012、2014、2018、2020、2023 等真题反复训练。

## 十一、IEEE 802.11 帧地址

视频讲解 802.11 帧中多个地址字段。

画面中明确强调：

- 地址1：接收地址，即直接接收该无线帧的节点。
- 地址2：发送地址，即实际发送该无线帧的节点。
- 地址3/地址4：取决于 To DS / From DS 的取值。

常见基础设施模式下：

- 主机 → AP：无线帧中的直接接收方是 AP。
- AP → 主机：无线帧中的直接发送方是 AP。

做题必须先判断帧是“去往 AP”还是“来自 AP”，再填地址字段。

## 十二、VLAN

视频后段讲 VLAN。

核心概念：

- 一个 VLAN 是一个逻辑广播域。
- VLAN 可以跨交换机组织，不必与物理位置一一对应。
- 不同 VLAN 默认不能直接二层互通。

## 十三、802.1Q 帧

视频展示 802.1Q 在以太网帧中插入 **4B VLAN 标记**。

因此：

- 原最大以太网帧长度可由 1518B 扩展到 1522B。
- VLAN Tag 中包含 VLAN 标识 VID。

视频板书强调：

**VID 用于说明该 802.1Q 帧属于哪个 VLAN。**

做最小帧长题时也要注意题目是否把额外 4B VLAN Tag 计入。

## 十四、交换机自学习

视频结尾用两个交换机和 A/B/C/D 主机演示交换表学习。

核心规则：

### 1. 学源地址

帧从某端口进入交换机时：

**把源 MAC 地址与入端口的映射写入交换表。**

### 2. 查目的地址

- 目的 MAC 已知 → 只从对应端口转发。
- 目的 MAC 未知 → 向除入端口之外的其他端口泛洪。
- 目的 MAC 对应端口恰好等于入端口 → 过滤，不再转发。

### 3. 多交换机链路

帧跨交换机时，每台交换机都根据“源 MAC + 入端口”独立学习自己的表项。

做题时沿着帧传播路径逐台交换机更新表，不能一次把最终答案写完。

## 十五、视频中的高频做题锚点

- 单帧发送 + 等 ACK → 停止-等待。
- 连续发多帧 + 累计确认 + 超时后连带重传 → GBN。
- 只重传真正丢失/错误帧 → SR。
- 序号 (n) bit + GBN → 常检查 (2^n-1)。
- SR 最大收发窗口 → 常检查 (2^{n-1})。
- RTT + 帧长 + 速率 → 信道利用率/窗口大小。
- To DS / From DS → 802.11 地址字段。
- VLAN Tag → 802.1Q、4B、VID。
- 交换机 → 学源地址、查目的地址、未知则泛洪。
