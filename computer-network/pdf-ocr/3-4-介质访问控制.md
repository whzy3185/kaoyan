## ALOHA 协议

### 纯 ALOHA

已确认原文要点：

- 总线形网络中，任何站点需要发送数据时，可以不进行检测直接发送。
- 若一段时间内未收到确认，则认为传输过程中发生冲突。
- 发送站点等待一段随机时间后再次发送，直到成功。
- 课件用 A、B、C、D 四个站点演示 B 向 C 发送，以及 A、B 同时发送时发生碰撞。
- A、B 同时发送发生碰撞后，两者都收不到确认。
- 因为重发等待时间随机，下一次发送可能避开碰撞。
- 课件指出纯 ALOHA 网络吞吐量较低，因此引出时隙 ALOHA。

### 时隙 ALOHA

已确认：

- 各站点时间同步。
- 时间被划分成等长时隙。
- 站点只能在每个时隙开始时发送帧。
- 发送一帧所需时间应小于等于时隙长度。
- 这样可以降低发生冲突的可能性。
- 冲突后的重传策略与纯 ALOHA 相似。

## CSMA 协议

课件解释缩写：

- **CS：Carrier Sense，载波监听**，发送帧前先检查总线上是否有其他站点发送数据。
- **MA：Multiple Access，多址接入**，多个站连接在一条总线上并竞争使用总线。

已确认原文逻辑：

- CSMA 通过载波监听装置监听信道。
- 发现信道空闲后再发送，可降低冲突概率。

课件列出三种：

1. 1-坚持 CSMA
2. 非坚持 CSMA
3. p-坚持 CSMA

### 1-坚持 CSMA

已确认：

- 监听到信道空闲时，以 1（100%）的概率立即发送。
- 若信道忙，则继续等待信道空闲。

### 非坚持 CSMA

已确认到的课件文字：

- 站点要发送数据时先监听信道。
- 若信道空闲则立即发送。
- 若信道忙，则放弃当前监听，等待随机时间后再监听。
